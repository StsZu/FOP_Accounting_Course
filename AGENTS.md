# Правила роботи агента в FOP Accounting Course

## Мета

Створювати й підтримувати україномовний курс «Бухгалтер ФОП: від нуля до професійного рівня» відповідно до `COURSE_CONTENT.md` і `TECHNICAL_SPEC.md`.

## Початок кожної роботи

1. Прочитати `TASK.md`, `STATUS.md`, `TECHNICAL_SPEC.md` і релевантну частину `COURSE_CONTENT.md`.
2. Для створення або перевірки модулів, квізів, джерел чи HTML використовувати локальний skill `$fop-course-builder`.
3. Перевірити фактичний стан файлів; не вважати заплановану структуру вже створеною.
4. Працювати з одним модулем або одним невеликим рівнем за раз.

## Джерела й вебпошук

- Дозволено без окремого підтвердження виконувати вебпошук, відкривати й читати загальнодоступні сторінки для дослідження та фактологічної перевірки курсу.
- Для податкових і юридичних тверджень використовувати передусім офіційні джерела: Верховна Рада України, ДПС, НБУ, ПФУ, Мінфін, Дія та інші компетентні державні органи.
- Пошук і читання не означають дозволу надсилати форми, входити до приватних кабінетів, публікувати курс або передавати дані зовнішнім сервісам.
- Не використовувати блог, форум або відповідь AI як єдине підтвердження правила.
- Для змінних правил фіксувати `valid_from`, `valid_to`, `last_verified`, `next_review`, `status`, URL і дату доступу.
- Не випускати матеріал зі статусом `stale`, `changed`, `repealed` або `needs_review`.

## Контент

- Писати українською і пояснювати терміни до їх професійного використання.
- Формулювати результати навчання як перевірювані дії.
- Чітко відділяти норму закону, офіційне роз’яснення, практичну рекомендацію та припущення.
- Не вигадувати ставки, ліміти, строки, форми, рахунки або функції електронних сервісів.
- Використовувати лише синтетичні або анонімізовані навчальні приклади.
- Квіз створювати лише після фактологічної перевірки уроку.
- Квіз не вважати достатнім доказом практичної навички.

## HTML-застосунок

- Зберігати модулі окремими Markdown- і JSON-файлами.
- Генерувати один публічний файл `dist/index.html` із вбудованим контентом і квізами.
- Не редагувати `dist/index.html` вручну.
- Не використовувати runtime-залежності, CDN, зовнішні шрифти або аналітику.
- Перевіряти роботу через `file://` і придатність до GitHub Pages.

## Безпека і межі

- Не подавати звітність, не підписувати документи, не здійснювати платежі й не використовувати КЕП.
- Не копіювати персональні або фінансові документи з бухгалтерського проєкту до курсу.
- Не публікувати курс без окремого дозволу користувача.
- Перед видаленням, масовим перейменуванням або зміною затвердженого матеріалу питати користувача.

## Завершення етапу

1. Запустити релевантні перевірки skill.
2. Оновити `STATUS.md`.
3. Якщо змінено затверджений матеріал, оновити `CHANGELOG.md` після його створення.
4. Зафіксувати неперевірені твердження й потребу в бухгалтерській або юридичній перевірці.
