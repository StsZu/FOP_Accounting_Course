# Реєстр дефектів і виправлень пілота

Дата: 2026-08-14
Версія до виправлень: `0.2.2-pilot` (стан модуля `0.2.0`)
Версія після виправлень: `0.3.0-pilot` (стан модуля `0.3.0`)
Метод: статичний аналіз `app/index.template.html`, JSON-вправ, квізу й скриптів + автоматична перевірка логіки зібраного `dist/index.html` через `tests/logic_smoke.mjs` (34 перевірки).

## Межі цієї перевірки

- Браузер у цьому середовищі недоступний, тому **не перевірено**: фактичний вигляд, контраст, типографіку, реальну клавіатурну навігацію, поведінку програм читання екрана та відкриття через `file://`. Ці пункти залишаються за користувачем і за повним аудитом із `TASK/CLAUDE_REVIEW_PILOT_COURSE.md`.
- Перевірено без браузера: рендер усіх дев'яти сторінок без винятків JavaScript, оцінювання Практики, Кейсу, Чекліста, Глосарію й квізу, пороги, ваги прогресу, версію ключа стану, відсутність зовнішніх ресурсів і мережевих викликів.
- Податкові й юридичні твердження модуля повторно не переоцінювалися: контент уроку не змінювався, тому людська перевірка від 14.08.2026 залишається чинною.

## F-01 — Кейс віддавав 27% балів без жодної дії

| Поле | Зміст |
|---|---|
| Пріоритет | `P1` |
| Тип | дефект / методика |
| Місце | `app/index.template.html` (`freshState`, `checkCase`), `curriculum/level_01/module_01_khto_takyi_fop/case_activity.json` |
| Спостереження | Початковий порядок дій формувався як `DATA.activities.case.actions.map(x=>x.id)`, а `checkCase` нараховував бал за кожну дію, що стоїть на позиції з того самого масиву. Тобто правильна послідовність була виставлена вже на старті: 6 із 22 балів (27%) учень отримував, не торкаючись кейсу; разом із двома неризиковими твердженнями — 36%. |
| Чому це проблема | Оцінювання винагороджувало бездіяльність, а найважливіша частина кейсу — побудова безпечної послідовності — фактично не перевірялася. |
| Рекомендація | Додано `initial_order` у `case_activity.json` (перемішаний порядок без жодної правильної позиції); шаблон бере його через `startOrder()` із безпечним фолбеком; версію стану підвищено, щоб старий збережений порядок не залишився правильним. |
| Очікуваний ефект | Порожній кейс дає 9% замість 36%; повністю правильне рішення — 100%. |
| Складність | мала |
| Стан | `fixed` |

## Перевірено й дефектом не є

- Статус «Не перевірено» у Чеклісті має порожнє значення, тому не може закрити пункт — збігається з інструкцією учня.
- Кнопка «Скинути весь прогрес» після очищення викликає повний `render()`, який перемальовує навігацію й прогрес; застарілого стану в шапці не залишається.
- У квізі «Наступне питання» з'являється лише після вибору відповіді, тому пропустити питання неможливо.
- Введення в поля Практики не викликає повного перемальовування, тому фокус і курсор не губляться.
- Ідентифікатори полів Практики придатні для CSS-селекторів.
