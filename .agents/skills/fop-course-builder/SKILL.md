# FOP Course Builder

## Робочий цикл

1. Прочитати кореневі `AGENTS.md`, `TASK.md`, `STATUS.md`, `TECHNICAL_SPEC.md` і релевантний розділ `COURSE_CONTENT.md`.
2. Перевірити фактичні файли. Не створювати порожню структуру наперед.
3. Працювати з одним модулем або невеликим рівнем.
4. Зібрати офіційні джерела й перевірити їх чинність до написання податкових або юридичних тверджень.
5. Створити модуль за [references/module-workflow.md](references/module-workflow.md).
6. Перевірити дати за [references/source-freshness.md](references/source-freshness.md) і запустити `scripts/check_freshness.py <project-root>`.
7. Після людської фактологічної перевірки створити сценарний квіз з окремим feedback для кожного варіанта й запустити `scripts/validate_quiz.py <quiz.json>`.
8. Створити інтерактивну практику, кейс, чекліст і мікроперевірки; кожна обов’язкова дія повинна мати критерій перевірки, пояснення помилки та `how_to` з видимою для учня послідовністю проходження.
9. Включити готовий модуль до єдиного `index.html`; не створювати окремий HTML модуля.
10. Перевірити сторінку «Як навчатися», вбудовані інструкції Практики, Кейсу й Чекліста, офлайн-роботу, навігацію, feedback, практичні дії, прогрес і відсутність зовнішніх runtime-залежностей.
11. Оновити `STATUS.md`; не завищувати фактичний статус.

## Джерела

- Вебпошук і читання загальнодоступних джерел дозволені без окремого підтвердження.
- Для податкових і юридичних правил використовувати офіційні першоджерела.
- Вказувати URL, дату доступу, `last_verified`, `next_review` і статус.
- Не випускати матеріал із простроченим або непідтвердженим критичним правилом.
- Відділяти норму закону від роз’яснення, рекомендації та припущення.

## Жорсткі межі

- Не вигадувати ставки, строки, ліміти, форми, рахунки чи функції сервісів.
- Не використовувати реальні персональні та фінансові документи як публічний матеріал.
- Не подавати документи, не підписувати, не платити й не публікувати GitHub Pages без окремого дозволу.
- Не створювати квіз до фактологічної перевірки уроку.
- Не редагувати згенерований `index.html` вручну.
- Не вважати успішний квіз достатнім підтвердженням практичної навички.

## Результат модуля

Модуль готовий лише коли має перевірюваний результат навчання, інтерактивну практичну дію, типовий сценарій помилки, негайний feedback, чинні джерела, людську перевірку, валідний сценарний квіз і коректне відображення в єдиному застосунку. Відкриття сторінки або ручна позначка «прочитано» не є доказом засвоєння.
